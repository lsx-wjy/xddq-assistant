# 寻道大千助手

寻道大千助手是一个面向《寻道大千》的多账号脚本管理与协议研究项目。它在原有命令行脚本基础上增加了可视化管理后台、账号与区服管理、自动任务编排、玩法协议浏览、逐项运行和实时日志，并提供适用于本机和云服务器的部署方案。

> 本项目为非官方工具，仅用于技术学习、个人研究和协议兼容性验证，与游戏开发商及运营方无关。

## 项目来源

本项目基于 `gyn7561/xddq-assistant` 原脚本进行扩展，感谢原作者提供的命令行脚本、游戏通信基础和功能实现。

- 原脚本地址：[https://github.com/gyn7561/xddq-assistant](https://github.com/gyn7561/xddq-assistant)
- 本扩展主要增加多用户管理、可视化界面、任务配置持久化、玩法协议目录、运行日志和 Docker 支持。

## 项目特点

- **多账号管理**：不提供默认账号；用户可自行添加、修改和查看账号资料，并从账号已有角色中读取区服名称与区服 ID。
- **手动控制连接**：保存账号不会自动连接，每个角色都可以独立连接或断开；已连接角色会自动成为其他模块的默认选择。
- **自动任务中心**：当前包含 52 条任务定义，其中 36 条已验证任务会显示在界面中，可按账号勾选、保存配置并一键依次运行。
- **持续任务支持**：自动砍树与装备处理等持续任务会循环执行，并持续输出砍树、装备替换或分解结果。
- **分类清晰**：自动任务按日常任务、福利礼包、挑战玩法、妖盟玩法、福地玩法、仙友与宗门、广告奖励、商店购买和定时任务分类。
- **玩法中心**：基于 APK/CDN 同步结果整理 220 个协议分组，支持查看功能详情、开放观察状态、请求参数和响应映射。
- **单项运行**：对具备请求定义且满足前置条件的功能，可在玩法详情中逐条运行并查看服务器返回结果。
- **实时日志**：自动任务页面和独立运行日志页面都会展示执行进度、成功、跳过和失败信息。
- **配置持久化**：账号、区服、功能勾选、自动任务参数和安全开关保存在 SQLite 数据库中，刷新页面或切换模块不会丢失。
- **安全控制**：战斗、购买和交易操作默认不授权；遇到服务器 `505` 登录限制时不会持续重连。

## 当前覆盖范围

项目针对 APK `4.1.10.10538` 同步并校验了：

- 5743 个消息类型；
- 220 个协议分组；
- 3179 个协议常量；
- 221 份 protobuf 定义；
- 36 项可在自动任务界面直接配置的脚本功能。

已经提供自动化流程的功能包括自动砍树与装备处理、仙树减时、冒险推图、镇妖塔、真火秘境、斗法、妖兽入侵、妖盟任务、福地采集、仙宫朝拜、宗门弟子、邮件奖励、免费礼包、月卡与终身卡、广告奖励、商店购买以及定时重启和福地重派等。

玩法中心展示协议覆盖情况，不代表每个协议都已经具备完整自动化逻辑。只有满足以下条件的功能才允许主动发送请求：

1. 请求与响应映射已经确认；
2. protobuf 定义完整；
3. 必要的角色数据和前置步骤已经取得；
4. 用户已开启对应的战斗、购买或交易授权。

官方 APK 中目前有 8 个请求和 8 个响应只有消息映射、缺少 protobuf 定义。项目会保留它们用于识别，但运行时会阻止发送，避免构造不完整的数据包。

## 管理后台

管理后台围绕普通用户的使用流程设计：

1. 在“用户管理”添加平台账号并读取角色区服；
2. 手动连接需要运行脚本的角色；
3. 在“自动任务”勾选功能并按需调整参数；
4. 点击“运行已选任务”，依次执行已启用功能；
5. 在任务页或“运行日志”查看实时结果；
6. 在“玩法中心”查看活动与协议详情，按需单独运行某一项请求。

主要页面如下：

| 页面 | 用途 |
| --- | --- |
| 总览 | 查看账号数量、连接状态、已选任务和运行状态 |
| 用户管理 | 添加、修改、连接或断开账号及角色 |
| 自动任务 | 分类勾选脚本功能、配置参数并运行任务队列 |
| 玩法中心 | 浏览协议分组、查看功能详情并逐项请求 |
| 运行日志 | 按账号和日志类型查看执行结果 |
| 系统设置 | 管理自动重连、数据快照及危险操作授权 |

## 技术架构

| 模块 | 技术与职责 |
| --- | --- |
| 游戏通信 | Node.js、WebSocket、protobufjs，负责登录、动态地址获取和游戏协议通信 |
| 管理服务 | Node.js HTTP 服务，提供用户、连接、任务和玩法 API |
| 管理界面 | Vue 3、TypeScript、Vite，提供响应式 Web 控制台 |
| 数据存储 | Node.js 内置 SQLite，按账号与区服保存配置和状态 |
| 生产部署 | Docker Compose，可接入常见 HTTPS 反向代理 |

运行环境要求 Node.js `22.5.0` 或更高版本，推荐 Node.js 24。

## 本机快速开始

在项目目录安装依赖并构建：

```powershell
Copy-Item account.js.sample account.js
npm ci
npm run build
```

启动可视化管理后台：

```powershell
npm run dashboard
```

然后访问 `http://127.0.0.1:4173`。账号需要在“用户管理”中自行添加，项目不会创建演示用户，也不会自动连接已保存账号。

如果只使用原始单账号命令行脚本，请先复制并编辑账号配置：

```powershell
Copy-Item account.js.sample account.js
npm start
```

## Docker 运行

项目提供 `Dockerfile` 和 `docker-compose.yml`。使用者可以根据自己的服务器、域名和反向代理环境进行部署：

```bash
docker compose up -d --build
```

生产环境应启用 HTTPS 和管理后台访问认证，并将 `data`、`logs` 目录持久化。请勿将包含账号资料的数据库、环境变量文件或备份文件公开。

## 常用命令

```powershell
npm run build              # 验证协议并构建管理界面
npm run dashboard          # 启动本地开发管理界面
npm run dashboard:build    # 只构建管理界面
npm run dashboard:serve    # 运行已构建的生产管理服务
npm run verify:protocols   # 校验协议映射与编解码
npm run protocol:sync      # 从 APK/CDN 同步协议资料
npm start                  # 启动原始单账号命令行脚本
```

## 数据与安全

- 用户数据保存在 `data/dashboard.sqlite`，其中可能包含用于连接游戏的账号密码，请勿提交、上传或公开该文件及其备份。
- 浏览器查询接口不会返回账号明文密码，前端也不会把密码写入浏览器存储。
- 生产管理服务支持 HTTP Basic Auth，并限制允许访问 API 的网页来源。
- `account.js`、SQLite 数据库、运行日志、构建依赖和本地临时文件不会包含在默认上传包中。
- 不要尝试通过高频登录或伪造请求规避服务器限制。出现 `505` 时应等待限制时间结束，并检查客户端版本、登录频率和连接状态。

## 协议升级验证

玩法中心的默认名称来自同版本 APK 的 `SystemInfoDB`、`LanguageWordDB` 和客户端 `systemOpenId`；分类由本项目维护，旧名称和活动主题别名保留用于搜索。公共协议结构等没有独立系统入口的分组使用项目说明名，不能把分组数量直接理解为独立活动数量。

升级协议后，可使用解压后的 APK 和已还原的客户端脚本同步名称与分类：

```powershell
npm run gameplay:sync -- --apk-root "G:/迅雷下载/744012834" --client-script "backups/client-4.1.10.10538.js"
npm run verify:gameplay-catalog
```

按实际位置替换路径；APK 与协议版本必须一致。同步生成 `web/src/features/activities/apkGameplayCatalog.json`，并在本地 `backups/` 输出差异报告；通过 `--report` 可指定报告目录。运行期活动换皮名称与开放状态仍以服务器数据为准。构建会检查全部协议分组是否都有名称、分类及一致的版本。

```powershell
node scripts/verify-gameplay-compatibility.mjs
node scripts/audit-protocol-upgrade.mjs --baseline "../old-checkout/src/game/config/grpc"
```

第一条命令使用模拟发送检查仙宫膜拜与领奖参数，不连接游戏。第二条命令将当前协议与旧版目录比较，报告默认保存在 `backups/compatibility-<版本>/`；可通过 `--output` 指定位置。发现跨版本解码不兼容时返回非零退出码，详细原因见 `audit.json`。旧版目录、账号数据及本地分析产物无需上传仓库。

`4.1.10.10538` 的 8041 个完整消息类型已通过合成数据编解码检查；登录、角色同步和门徒、仙宫、药园的只读查询已完成实测。合成测试与只读查询不能证明所有自动任务兼容：药园存在新增必填字段，冒险、镇妖塔、斗法仍有既有的无请求体协议支持缺口，战斗、购买和领奖等操作尚未逐项实测。

## 使用须知

游戏版本更新可能改变登录接口、WebSocket 地址、消息编号或 protobuf 结构。更新后应先同步并验证协议，再启用相关任务。未验证的功能即使出现在玩法目录中，也不应视为已经支持自动运行。

使用者应遵守游戏服务条款和所在地法律法规，自行承担账号限制、数据损失及其他使用风险。请勿出售本项目、他人账号数据或利用本项目从事未经授权的行为。
